# Plans

`docs/PLANS/` is for execution plans for multi-hour or multi-PR work.

## When To Create A Plan

- The task will likely take more than one focused session.
- The task spans app + DB + functions or has risky sequencing.
- The work needs checkpoints, rollback notes, or handoff clarity.

## File Naming

- `YYYY-MM-DD-short-topic.md`
- Example: `2026-02-17-notifications-reliability.md`

## Minimum Plan Sections

1. Context and goal
2. Scope and non-goals
3. Constraints/risks
4. Step-by-step execution
5. Verification strategy
6. Rollback or mitigation plan
7. Progress log (dated updates)

Use `docs/PLANS/TEMPLATE.md` as the default skeleton.
