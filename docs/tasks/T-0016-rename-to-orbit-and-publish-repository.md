# Переименование проекта в Orbit и публикация репозитория

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log` и `Outcomes & Retrospective` must be kept up to date as work proceeds.

Требования к формату и содержанию этого документа заданы в `docs/PLANS.md` (от корня репозитория). Документ обязан поддерживаться в соответствии с ним.

## Purpose / Big Picture

Репозиторий сейчас приватный и называется `Orbit`. Из этого следуют две независимые проблемы.

Первая — техническая, и она блокирует всю работу. У приватных репозиториев на бесплатном плане GitHub есть месячный лимит минут GitHub Actions. Лимит исчерпан, поэтому джобы больше не получают исполнителя («раннер» — виртуальная машина, на которой GitHub выполняет шаги пайплайна) и падают за две секунды, не выполнив ни одного шага. Никакая правка кода этого не чинит: пайплайн не может стать зелёным, пока репозиторий приватный. У публичных репозиториев стандартные раннеры бесплатны и без месячного лимита, поэтому публикация — это и есть починка пайплайна.

Вторая — репозиторий нельзя показать. В рабочем дереве и в истории коммитов лежат персональные данные владельца, нет README и файла лицензии, а само имя проекта содержит нецензурное слово и останется видимым в каждом старом коммите, даже если переименовать файлы сегодняшним коммитом.

После выполнения этого плана человек сможет открыть `https://github.com/mpodreshetnikov/orbit` в браузере без входа в аккаунт и увидеть работающий публичный проект: README с описанием и командами запуска, файл лицензии MIT, вкладку Actions с зелёным прогоном. Поиск по всей истории репозитория не найдёт ни личной почты владельца, ни его Google-идентификатора, ни старого имени проекта.

Проверить результат можно так: открыть репозиторий в приватном окне браузера (без авторизации) — страница должна открыться, а не отдать 404; во вкладке Actions последний прогон на ветке `main` должен быть зелёным; команда `git clone` с последующим `git log -S` по личной почте владельца должна вернуть ноль совпадений.

## Surprises & Discoveries

- Observation: красный пайплайн не имеет отношения к содержимому изменений — джобам не выделяется раннер.
  Evidence: у упавших джоб `runner_id: 0` и пустое `runner_name`, `started_at` и `completed_at` расходятся на две секунды, список шагов пуст. Та же подпись на несвязанной ветке `claude/open-tasks-priority-jn7glx` в 12:06 на третьей попытке. Последний прогон с живыми раннерами — push в `main` в 07:50, где `Secret Scan` и `Quality Gates` прошли успешно.

- Observation: единственная находка `gitleaks` по всей истории — ложное срабатывание.
  Evidence: правило `generic-api-key` в `supabase/seed.sql` сработало на UUID демонстрационного пользователя в комментарии. Это не учётные данные, но энтропии строки хватало для срабатывания, поэтому значение заменено на низкоэнтропийное вместо подавления находки по отпечатку.

- Observation: перевод Vercel MCP на переменную окружения ломал `mcp-sync` целиком, а не только один сервер.
  Evidence: `mcp/.env` в `.gitignore`, поэтому у существующих рабочих копий новой переменной нет; `resolveHttpUrl()` в `scripts/sync-mcp-configs.ts` бросает исключение, и команда падает с `sync:mcp failed: Server "vercel" requires env var "MCP_VERCEL_URL" for HTTP URL generation.`, не сгенерировав ни одного конфига.

- Observation: `just dev` и `just dev-ready-local` — одно и то же.
  Evidence: `justfile:269-270`, рецепт `dev` разворачивается в `dev-ready-local true {{auth}}`. Написанный подряд запуск обеих команд поднимал один стек дважды и конфликтовал за порты.

- Observation: старое имя проекта не встречается в метаданных Git.
  Evidence: `git log --all --format='%H %s%n%b' | grep -ic 'orbit'` возвращает `0`, тегов в репозитории нет. Значит, переписывание истории затронет только содержимое файлов и пройдёт без переписывания сообщений коммитов.

- Observation: первичный аудит пропустил ещё один вид персональных данных — локальные пути с именем пользователя Windows. Нашлись они только при переименовании, потому что содержали в себе имя проекта.
  Evidence: `.playwright/cli.config.json` в отслеживаемых файлах содержал `C:/Users/dev/Documents/Coding/Orbit/browserExtension/dist` в аргументах запуска браузера, и такой же путь стоял в `docs/tasks/T-0001-canonical-categories-and-rule-pipeline.md:430`. Помимо утечки имени пользователя это делало конфигурацию непригодной для кого-либо, кроме владельца; пути заменены на относительные от корня репозитория. В истории путь встречается в одном коммите (`c17353d`). Отдельно проверено, что вхождения `/Users/jesse/` в `.agents/skills/systematic-debugging/` — это примеры из стороннего скилла, а не данные владельца, и они оставлены как есть.

- Observation: переписывание истории на месте не убрало бы персональные данные — GitHub хранит копии старых коммитов в служебных ссылках `refs/pull/*`, которые нельзя удалить владельцу репозитория.
  Evidence: в зеркальном клоне до рерайта `refs/pull/9/head` содержит `supabase/seed.sql` с четырьмя вхождениями личной почты. Такие ссылки заводятся на каждый открытый PR, а их в репозитории было 28. На публичном репозитории они доступны любому через `git fetch origin 'refs/pull/*:refs/remotes/origin/pr/*'`. Удалить их может только поддержка GitHub. Отсюда решение о новом репозитории.

- Observation: масштаб персональных данных был недооценён на порядок, потому что первичный подсчёт вёлся по одной ветке.
  Evidence: по ветке выходило шесть коммитов с почтой. По всем ссылкам зеркала — 320 коммитов, в которых почта встречается в 1324 парах коммит-файл, Google `sub` в 311, путь с именем пользователя Windows в 169.

## Decision Log

- Decision: публиковать репозиторий под лицензией MIT.
  Rationale: без файла лицензии опубликованный код формально остаётся «все права защищены» — его нельзя законно использовать, и это читается как незавершённость. MIT — самый распространённый и понятный вариант для личного проекта, который открывают «чтобы посмотреть».
  Date/Author: 2026-08-13 / выбор владельца

- Decision: переписать историю коммитов, а не ограничиться правкой текущего дерева.
  Rationale: персональные данные лежат в шести старых коммитах, а Google-идентификатор — в одном. После публикации они останутся читаемыми через API и любой форк, и переписать историю будет уже невозможно. Окно для этой операции — пока репозиторий приватный и без форков.
  Date/Author: 2026-08-13 / выбор владельца

- Decision: в том же проходе переписывания истории заменить старое имя проекта на `orbit`.
  Rationale: имя содержит нецензурное слово. Если заменить его только сегодняшним коммитом, оно останется видимым в каждом старом коммите и в каждом диффе публичного репозитория, что обесценивает переименование. Проход по истории уже выполняется ради персональных данных, поэтому дополнительная замена не добавляет отдельного риска. Если это окажется нежелательным, строку с именем достаточно убрать из файла замен — остальная часть прохода от этого не зависит.
  Date/Author: 2026-08-13 / автор плана

- Decision: переименовать идентификаторы протокола расширения (`orbit-webapp`, `orbit-extension` в `browserExtension/src/core/content-bridge.ts`).
  Rationale: это строки рукопожатия между веб-приложением и установленным расширением, и их переименование разрывает совместимость с уже установленной копией расширения до её обновления. Приложение однопользовательское и self-hosted, разрыв восстанавливается переустановкой расширения. Ломать совместимость один раз сейчас, до публикации, дешевле, чем оставлять старое имя в протоколе навсегда.
  Date/Author: 2026-08-13 / автор плана

- Decision: значение по умолчанию для имени сервиса в телеметрии меняется на `orbit`, а непрерывность истории метрик обеспечивается переменной окружения на стороне владельца.

Оставить в публичном коде старое имя ради своих дашбордов — значит объяснять читателю несуществующую сущность. Владелец сохраняет непрерывность, выставив `OBS_APP=orbit` в своём окружении; в публичном коде по умолчанию стоит `orbit`.
  Date/Author: 2026-08-13 / автор плана

- Decision: сливать PR #28 и PR переименования в `main` при красном пайплайне.
  Rationale: пайплайн не может стать зелёным до публикации, а публикация не должна происходить до вычистки истории, которая, в свою очередь, требует, чтобы изменения уже были в `main`. Это не обход проверки, а следствие порядка: проверки выполняются локально до слияния и повторно в CI сразу после публикации.
  Date/Author: 2026-08-13 / автор плана

Сессия, в которой выполняется работа, ограничена одной веткой `claude/public-repository-risks-zqfsoy`, и открытие второй ветки потребовало бы отдельного разрешения. Разделение на два коммита даёт то же свойство — переименование читается само по себе через `git show`, — не требуя второго PR.

- Decision: вместо переписывания истории на месте создан новый репозиторий `Orbit`, а старый `Supabitch` остаётся приватным архивом.
  Rationale: ссылки `refs/pull/*` нельзя удалить владельцу, поэтому force-push в существующий репозиторий оставил бы данные доступными после публикации. Альтернатива — просить поддержку GitHub вычистить их — ставит необратимый шаг в зависимость от сроков, на которые повлиять нельзя, и всё это время репозиторий обязан оставаться приватным, то есть пайплайн остаётся сломанным. У репозитория ноль звёзд и ноль форков, единственная ценность старого — тексты PR, и они сохраняются в приватном архиве. Старый репозиторий не должен становиться публичным никогда: именно приватность держит `refs/pull` закрытыми.

## Context and Orientation

Репозиторий содержит одно приложение на Next.js поверх Supabase, расширение для Chrome, набор Edge-функций на Deno и коннектор MCP. Полная карта поверхностей — в `docs/ARCHITECTURE.md`.

Разбираться нужно в четырёх местах.

**Где живёт имя проекта.** Строка `orbit` в разных написаниях встречается 127 раз в 45 файлах. Большинство вхождений безопасны — документация, тесты, внутренние имена вроде `__orbitNodeOtelSdk` в `src/lib/observability/server-otel.ts`. Несущих мест четыре. В `browserExtension/src/core/content-bridge.ts` первые две строки задают `WEBAPP_SOURCE` и `BRIDGE_SOURCE` — идентификаторы, по которым веб-приложение и расширение узнают друг друга в обмене сообщениями. В `src/lib/observability/config.ts:79` имя попадает в поле `service.name` телеметрии, по которому строятся запросы в Grafana. В `supabase/config.toml:5` поле `project_id` определяет имена локальных Docker-контейнеров Supabase. В `browserExtension/manifest.json` имя и описание видны пользователю в браузере.

Отдельно проверено и признано безопасным: имя артефакта релиза расширения строится функцией `getExtensionReleaseArtifactName()` в `scripts/extension/release.ts:133` из номера версии, а `latest.json` хранит явный `download_url`. Поэтому переименование затронет только будущие релизы, а уже загруженные в хранилище объекты продолжат скачиваться по старым путям.

**Что за персональные данные.** В `supabase/seed.sql` до PR #28 лежала настоящая учётная запись Google: почта, полное имя, ссылка на аватар и поле `sub` — устойчивый идентификатор аккаунта, по которому профили сопоставляются между сервисами; это самая чувствительная часть, потому что это не отображаемое значение, а идентификатор. Та же почта была зашита как значение по умолчанию для обхода авторизации в разработке ещё в десяти файлах. В рабочем дереве всё это уже заменено на нейтральные заглушки, но в истории коммитов сохраняется: почта в шести коммитах, `sub` — в одном.

**Почему пайплайн красный.** Описано в разделе «Purpose / Big Picture» и подтверждено в «Surprises & Discoveries». Важное следствие для порядка работ: проверять изменения до публикации можно только локально.

**Что уже сделано.** PR #28 (`claude/public-repository-risks-zqfsoy`) содержит два коммита: вычистку персональных данных из дерева вместе с добавлением README и лицензии, и правку двух замечаний ревью. Этот план продолжает работу с того места.

## Plan of Work

Работа делится на шесть этапов, и их порядок жёстко задан двумя ограничениями. Историю можно переписать только до публикации, потому что после появления публичных форков старые коммиты остаются доступными навсегда. А пайплайн можно проверить только после публикации, потому что до неё ему не выделяются раннеры. Между этими двумя ограничениями и находится вся последовательность.

**Milestone 1 — гигиена репозитория.** Выполнен. Персональные данные убраны из рабочего дерева, добавлены README и лицензия MIT, Vercel MCP отвязан от личного слага и переведён в режим opt-in.

**Milestone 2 — переименование.** В рабочем дереве не остаётся ни одного вхождения старого имени ни в одном написании. Отдельным коммитом, чтобы дифф переименования читался как переименование и не смешивался с вычисткой данных.

**Milestone 3 — слияние.** PR #28 попадает в `main`. Пайплайн при этом красный, и это ожидаемо: проверки прогоняются локально непосредственно перед слиянием.

**Milestone 4 — переписывание истории.** Из всех коммитов исчезают персональные данные и старое имя. Это единственный необратимый шаг плана, и выполняется он на свежем клоне, чтобы рабочая копия оставалась нетронутой на случай ошибки.

**Milestone 5 — публикация.** Репозиторий переименовывается и становится публичным, включаются защитные настройки, которые публичность делает необходимыми.

**Milestone 6 — проверка.** Пайплайн запускается на бесплатных раннерах и должен стать зелёным. Это первая настоящая проверка изменений в CI за весь план.

Все команды выполняются из корня репозитория, если не указано иное.

### Milestone 2 — переименование

Замена выполняется по всем файлам под контролем версий, с сохранением регистра. Три написания покрывают все 127 вхождений: строчное, с заглавной первой буквой и полностью заглавное.

    FILES=$(git grep -il 'orbit' -- .)
    sed -i -e 's/orbit/orbit/g' -e 's/Orbit/Orbit/g' $FILES
    FILES=$(git grep -l 'ORBIT' -- .)
    sed -i 's/ORBIT/ORBIT/g' $FILES

Полностью заглавное написание встречается только в `__ORBIT_APP_ENV_KIND__` — это поле, которое веб-приложение выставляет на `window`, чтобы страница знала, работает она в разработке или в продакшене; оно объявлено в `src/app/money/import/extension-release-client.ts` и используется в тестах.

Проверить, что не осталось ничего:

    git grep -in 'orbit' -- .

Команда должна не найти совпадений. Затем убедиться, что несущие места получили ожидаемые значения: `package.json` — `"name": "orbit"`, `supabase/config.toml` — `project_id = "orbit"`, `browserExtension/src/core/content-bridge.ts` — `orbit-webapp` и `orbit-extension`.

Перед переименованием нужно остановить локальный стек, иначе смена `project_id` оставит висеть контейнеры и тома со старыми именами:

    just dev stop

Прогнать проверки и закоммитить.

### Milestone 3 — слияние

Локально прогнать полный набор проверок на ветке переименования, потому что в CI это сделать нельзя:

    npx prettier --check .
    npx vitest run
    just quality

Отдельно прогнать сценарий базы данных, который до сих пор ни разу не выполнялся против изменённого `supabase/seed.sql`, — для него нужен запущенный Docker:

    just dev-ready-local

После этого слить PR #28 и PR переименования в `main`. Пайплайн будет красным по причине, описанной выше.

### Milestone 4 — переписывание истории

Шаг необратимый. Выполняется на свежем клоне, рабочая копия не затрагивается.

Понадобится `git-filter-repo` — инструмент для массового переписывания истории Git:

    pip install git-filter-repo

Сделать свежий клон и перейти в него:

    git clone https://github.com/mpodreshetnikov/Orbit.git /tmp/orbit-rewrite
    cd /tmp/orbit-rewrite

Собрать файл замен во временном каталоге. Он не коммитится — в нём лежат ровно те строки, которые удаляются. Пять значений нужно взять из истории, потому что в текущем дереве их уже нет: почта владельца, его полное имя, значение `sub`, ссылка на аватар и UUID демонстрационного пользователя. Все пять видны в любой версии `supabase/seed.sql` до PR #28, например:

    git show d048608:supabase/seed.sql | sed -n '18,50p'

Файл замен имеет формат «искомое`==>`замена», по одной паре на строку. Строка для имени владельца записывается как регулярное выражение с отрицательным ретроспективным утверждением, чтобы не задеть строку копирайта в `LICENSE`, где имя правообладателя должно остаться:

    <почта владельца>==>dev@example.com
    regex:(?<!Copyright \(c\) 2026 )<Имя Фамилия>==>Dev User
    <значение sub>==>100000000000000000001
    <ссылка на аватар>==>https://example.com/avatar.png
    <UUID демо-пользователя>==>00000000-0000-4000-8000-000000000001
    Users/dev==>Users/dev
    Users\dev==>Users\dev
    orbit==>orbit
    Orbit==>Orbit
    ORBIT==>ORBIT

Две строки с `Users` убирают из истории локальный путь с именем пользователя Windows — он встречается в одном коммите и описан в разделе «Surprises & Discoveries». Записаны оба варианта разделителя, потому что путь встречался и с прямым, и с обратным слэшем.

Отдельно готовится файл `mailmap`, который переносит авторство коммитов с личной почты на служебный адрес GitHub, уже используемый в четырнадцати коммитах. Так атрибуция сохраняется, а адрес из метаданных исчезает:

    Dev User <44291329+mpodreshetnikov@users.noreply.github.com> <почта владельца>

Запустить проход:

    git filter-repo --force --replace-text <файл замен> --mailmap <файл mailmap>

Проверить результат до отправки. Для каждой из удаляемых строк число совпадений по всей истории должно быть нулевым:

    git rev-list --all | xargs -I{} git grep -l '<строка>' {} 2>/dev/null | wc -l

Убедиться, что строка копирайта уцелела и что список авторов больше не содержит личной почты:

    git show HEAD:LICENSE | sed -n '3p'
    git log --all --format='%ae' | sort -u

Прогнать сканер секретов по переписанной истории — находок быть не должно:

    gitleaks detect --source . --config .gitleaks.toml --no-banner

Только после того как все проверки прошли, отправить результат:

    git remote add origin https://github.com/mpodreshetnikov/Orbit.git
    git push --force --all origin

Удалить временный файл замен.

### Milestone 5 — публикация

В настройках репозитория на GitHub выполняются четыре действия. Переименовать репозиторий в `orbit` (Settings → General → Repository name); GitHub оставит перенаправление со старого адреса, но `git remote` в локальных клонах нужно обновить вручную. Сменить видимость на публичную (Settings → General → Danger Zone → Change visibility). Включить сканирование секретов вместе с защитой при отправке (Settings → Code security). Настроить защиту ветки `main` и обязательных ревьюеров для окружения `production`, иначе любая отправка в `main` уходит в продакшен.

Отдельно проверить, что переименование репозитория не сломало внешние привязки: проекты Vercel и Supabase от имени репозитория не зависят, но интеграция Vercel с GitHub указывает на репозиторий и может потребовать переподключения.

### Milestone 6 — проверка

Запустить пайплайн заново на `main` и убедиться, что джобы получают раннер и проходят. Признак починки — у джобы непустое `runner_name` и ненулевой `runner_id`, а длительность измеряется минутами, а не секундами.

## Validation and Acceptance

Приёмка формулируется как наблюдаемое поведение.

Открыть `https://github.com/mpodreshetnikov/orbit` в приватном окне браузера без входа в аккаунт. Страница открывается, а не отдаёт 404. На главной отрисован README с заголовком `Orbit`, рядом отображается лицензия MIT.

Клонировать репозиторий заново и убедиться, что персональных данных нет ни в одном коммите. Каждая из команд возвращает пустой вывод:

    git log --all -S'<почта владельца>' --oneline
    git log --all -S'<значение sub>' --oneline
    git log --all -S'orbit' --oneline

Список авторов не содержит личной почты:

    git log --all --format='%ae' | sort -u

Во вкладке Actions последний прогон на `main` зелёный, а у его джоб указан конкретный раннер. Это одновременно подтверждает и то, что публикация сняла ограничение по минутам, и то, что изменения проходят проверки — впервые за весь план в реальном CI.

Локально стек поднимается под новым именем: после `just dev` контейнеры Supabase имеют префикс `orbit`, приложение открывается, а вход через обход авторизации в разработке работает с адресом `dev@example.com`.

## Idempotence and Recovery

Milestones 1–3 полностью обратимы: это обычные коммиты, любой из них откатывается через `git revert`.

Milestone 4 необратим после отправки с `--force`. До отправки он безопасен полностью, потому что выполняется на отдельном клоне: если проверки не сошлись, каталог клона удаляется и проход повторяется с нуля, а исходный репозиторий на GitHub при этом не изменился. Само переписывание идемпотентно по смыслу — повторный проход по уже очищенной истории просто не найдёт что заменять. Перед отправкой стоит сохранить резервную копию ветки на случай, если ошибка обнаружится позже:

    git clone --mirror https://github.com/mpodreshetnikov/Orbit.git /tmp/orbit-backup.git

После успешной публикации эту копию нужно удалить: в ней остаются те самые персональные данные.

Milestone 5 частично обратим. Репозиторий можно вернуть в приватное состояние, но это не отменяет того, что содержимое было доступно публично: если персональные данные уйдут в публичный доступ, обратное переключение их не вернёт. Именно поэтому Milestone 4 обязан быть завершён и проверен до Milestone 5. Переименование репозитория обратимо и безопасно.

Если после публикации выяснится, что в истории что-то осталось, порядок действий такой: немедленно вернуть репозиторий в приватное состояние, выполнить ещё один проход `filter-repo`, и считать утёкшие значения скомпрометированными — то есть при необходимости заменить их, а не только удалить из истории.

## Artifacts and Notes

После переписывания истории отпечаток в `.gitleaksignore` будет ссылаться на хеш коммита, которого больше не существует. Это безвредно — запись просто перестанет на что-либо указывать, — но её стоит убрать при ближайшей правке файла, чтобы не вводить в заблуждение.

Владельцу, чтобы сохранить непрерывность истории метрик в Grafana после смены имени сервиса, нужно выставить `OBS_APP=orbit` в своём окружении. Без этого метрики до и после переименования будут видны как два разных сервиса.

Уже установленная копия расширения перестанет общаться с веб-приложением после переименования идентификаторов протокола, пока её не соберут и не установят заново из обновлённого исходника.

Этот файл — единственный в репозитории, который осмысленно употребляет старое имя, и проход `filter-repo` из Milestone 4 заменит его и здесь. После переписывания истории отдельные фразы плана будут читаться как «переименование `orbit` → `orbit`». Это ожидаемый косметический побочный эффект: делать для одного файла исключение в проходе по истории означало бы оставить старое имя в публичном репозитории ровно там, где оно набрано полностью и много раз. Смысл документа восстанавливается из контекста, а фактическая история работы сохраняется в этом разделе и в `Decision Log`.

## Interfaces and Dependencies

Для Milestone 4 нужен `git-filter-repo` и `gitleaks`. Для локальной проверки в Milestone 3 нужен запущенный Docker, без него сценарий базы данных прогнать нельзя.

Milestone 5 требует прав администратора репозитория и выполняется человеком через веб-интерфейс GitHub — автоматизировать его в рамках этого плана не предполагается.

План не зависит от других задач реестра и ничего в нём не блокирует.
